## 아직 하지 말 것

### 탐색: 관련 파일 후보와 책임 확인

- `payment_failed`와 `refunded` 중 어떤 상태를 추가할지 선택하거나, 후보 파일의 수정 순서를 계획으로 확정하지 않는다.

### 탐색: 현재 동작과 테스트 공백 확인

- `FAIL` 결제의 HTTP 응답과 실패 주문 재결제 허용 여부를 결정하거나, 공백을 채울 테스트 변경안을 작성하지 않는다.

### 결정: 미결정 정책 확인

- 선택된 정책을 특정 파일·함수·테스트의 변경 목록으로 변환해 수정 범위를 계획하지 않는다.

### 계획: 수정 범위와 검증 계획 작성

- 계획에 적힌 주문 상태·결제·재고·관리자 조회 동작을 구현하거나 테스트 코드로 작성하지 않는다.

## Human Gate

### 게이트 1 — 도메인·관리자 표현 확정

- 어느 작업 뒤인지: 탐색: 관련 파일 후보와 책임 확인
- 사람이 확인할 질문:
  - `OrderStatus`에 이번 변경으로 어떤 상태를 추가할까요?
  - 관리자 주문 목록에서 실패 정보를 어떻게 표시할까요?
- 승인 전에 하지 않을 것: 주문 상태의 추가 범위나 관리자 목록의 실패 정보 표시 방식을 확정하지 않으며, 이를 바탕으로 도메인 모델·관리자 조회·응답 형식의 수정 범위를 계획하거나 변경하지 않는다.

### 게이트 2 — 결제 실패 처리·검증 범위 확정

- 어느 작업 뒤인지: 탐색: 현재 동작과 테스트 공백 확인
- 사람이 확인할 질문:
  - `FAIL`로 시작하는 카드 토큰의 결제 실패 응답은 무엇으로 할까요?
  - `payment_failed` 주문의 재결제를 어떻게 처리할까요?
  - 테스트 범위에 어떤 결제 실패·재결제 시나리오를 포함할까요?
- 승인 전에 하지 않을 것: 결제 실패의 HTTP 응답, 실패 주문의 후속 처리, 재결제 관련 동작 또는 해당 검증 시나리오를 선택하지 않으며, 결제·재고·테스트의 수정 범위를 계획하거나 변경하지 않는다.

## 멈춤 조건

### 정보 부족

- 판정 기준: `notes/order-status-request.md`의 완료 조건 또는 `notes/pending-decisions.md`의 질문 하나에 대해, 관련 파일 후보와 현재 동작을 모두 확인한 뒤에도 그 항목의 책임 파일·현재 동작·선택에 필요한 사실 중 하나를 확인할 수 없으면 멈춘다.
- 멈춘 뒤 남길 것: 수행한 탐색 작업과 확인한 파일·사실, 확인하지 못한 항목 때문에 멈춘 이유, 재개에 필요한 파일 접근 권한·실행 결과·사람의 사실 확인을 남긴다.

### 범위 초과

- 판정 기준: 완료 조건을 충족하려면 주문 상태·결제·재고·관리자 조회 이외의 기능을 변경해야 하거나, `notes/pending-decisions.md`에 없는 새 정책 결정을 선택해야 하면 멈춘다.
- 멈춘 뒤 남길 것: 수행한 범위와 추가로 필요한 변경 대상, 요청 범위를 벗어난 지점 때문에 멈춘 이유, 재개에 필요한 범위 승인 또는 새 정책 결정을 남긴다.

### 검증 불가

- 판정 기준: 계획한 각 완료 조건에 대응하는 테스트 또는 관찰 방법을 하나 이상 정할 수 없거나, 정한 방법을 실행하는 데 필요한 명령·의존성·테스트 데이터 중 하나가 없어 결과를 확인할 수 없으면 멈춘다.
- 멈춘 뒤 남길 것: 수행한 범위와 시도한 검증 방법·결과, 검증 결과를 확인할 수 없어 멈춘 이유, 재개에 필요한 실행 명령·의존성·테스트 데이터 또는 검증 기준을 남긴다.
